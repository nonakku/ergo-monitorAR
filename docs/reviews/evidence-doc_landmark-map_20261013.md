## 対象、根拠と読者課題

ユーザー指摘は、MediaPipeの人体と番号の対応図がなく、技術説明が文章で完結していること。今回の改訂は3.4.4の説明・図・全33点表と根拠・引き継ぎ一式。アプリの機能・計算式・依存版を変更しない。

番号の根拠は固定コミットの [公式旧Pose定義](../references/mediapipe/upstream-pose-landmarks.py.txt)、採用JSの `POSE_LANDMARKS` / `POSE_CONNECTIONS`、アプリの `updateUI` / `drawSkeleton`。公式サイトのPNGは接続が403で拒否され未取得。今回の2図はこれらの根拠に照合した独自の模式図であり、公式転載画像・推定結果・画面画像・実測データではない。[出典と取得記録](../references/mediapipe/landmark-map-source.json) を保存した。

事前課題は次の4件。全て本文と2図を併読して回答できることを今回の必須条件とした。根拠監査担当はコードから期待解答を独自に作り、読者役へ著者の解答や他担当の結論を先に渡していない。

| ID | 課題 | 合格条件 |
| --- | --- | --- |
| M1 | 人物の左手首、右かかと、口の左右端を探す | 図の位置と番号を示し、人物自身の左右を画面の左右と混同しない |
| M2 | 指の点はあるが指線・顔・足先が画面にない場合を判断 | 描画仕様と推定失敗を区別し、点・線・計算の対象を分ける |
| M3 | 左膝・体幹角度の入力と右膝拡張の変更範囲を説明 | 頂点、左右肩/腰の中点、変更する呼出・表示・評価ルールを特定 |
| M4 | 9/10を英字プロパティで参照する注意を説明 | 公式Python名と採用JSの名前を区別し、原因を断定しない |

実読者の試読、実カメラ精度、印刷・色覚条件は今回の静的資料確認の代替にはならず、未実施として残す。

## 照合方法と結果

- 全33点表を公式ソースの番号/英名と機械比較し、完全一致を確認。採用JSとの差は9=`LEFT_RIGHT`、10=`RIGHT_LEFT`の2名称だけで、本文に明記。
- 図3-1のSVGから `data-landmark` を持つ点を抽出し、0～32の集合、色別の利用集合を照合。15/16は全身と手拡大に再掲し、35個の描画点が33種類を表す。
- SVGの各線の端座標を番号付き点に戻し、公式35接続と一致、実線12接続はアプリの配列と一致、破線23接続は差集合と一致を確認。独立監査も同じ集合照合を実施。
- 図3-2の入力6点、S/Hの中点座標とx/y平均式、左膝25の頂点、角度関数と本文の対応を確認。
- ChromiumでSVGを表示してPNGを生成し、保存したPNG2枚を著者と独立担当が実際に視認した。描画したのは模式図で、アプリの画面撮影ではない。
- 保存原文のSHA-256、3.4.4内のローカルリンクとコード行参照を照合し、保存後の本文も読み直した。
- 元アプリの全追跡ファイルに差分なし。今回は文書・図の変更であり、既に保存した模擬カメラ等の実行結果を今回の実カメラ検証として流用しない。

機械照合の結果と保存図のハッシュは [確認結果JSON](landmark-map_checks_20261013.json)。原文・SVG・PNGは引き継ぎZIPにも同梱する。
