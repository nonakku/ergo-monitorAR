# シックスハット思考法ブレインストーミング

エドワード・デボノのSix Thinking Hatsに基づき、一つの議題を6つの視点（帽子）へ意図的に分離して検討する。視点を混在させたまま考えると、批判と発想と感情が同じ発言の中で衝突し、どの視点からの発言かが判別できなくなる。帽子ごとに視点を固定することで、この衝突を防ぐ。

## 6つの帽子

| 帽子 | 視点 | やること |
|---|---|---|
| 白 | 事実・情報 | 分かっている事実、分かっていない事実、必要なデータを分ける。意見や解釈を混ぜない |
| 赤 | 感情・直感 | 理由を述べずに、直感・違和感・好悪を言葉にする。正当化しない |
| 黒 | リスク・弱点 | 危険性、実行不可能な理由、論理的な欠陥を指摘する。批判のための批判ではなく、根拠を伴う懸念に限る |
| 黄 | 便益・楽観 | 価値、実現可能性、うまくいく根拠を挙げる。願望ではなく論理的な裏付けを伴う |
| 緑 | 創造・代案 | 新しい選択肢、視点の転換、既存案の組み替えを出す。案の良し悪しの判断はここでは行わない |
| 青 | 進行・統合 | 議論の設計、要約、次の一手の決定。他の帽子の内容を混ぜて再検討しない |

## トリガー

「ブレインストーミング」「アイデア出し」「多角的に検討」「企画を考えたい」「この問題をどう解決するか整理したい」など、発散的な検討を求める依頼全般で起動する。手法名の明示は不要。

## 実行手順

### 1. 議題を確定する

依頼から議題（何について検討するか）を特定する。議題があいまいな場合は、この一点のみ確認する。目的・制約・関係者など議題の周辺情報は、白帽子の中で「分かっていること」として扱えばよく、着手前に別途聞く必要はない。

### 2. 帽子の順序を決める

目的に応じて実行するAIが順序を決め、本文には決めた順序と理由を一行で示す。ユーザーへ順序の選択を委ねない（構成・順序の選択はAIの裁量範囲）。

- 新規アイデア創出が主目的の場合: 青(導入)→白→緑→黄→黒→赤→青(統合)
- 既存案の採否判断が主目的の場合: 青(導入)→白→黄→黒→緑→赤→青(統合)
- 対立が生じている議題の場合: 青(導入)→赤→白→黒→黄→緑→青(統合)

### 3. 各帽子を実行する

帽子ごとに以下を満たす。一行の結論だけで終わらせない。

- **白**: 既知の事実／未確認の事実／必要な追加情報の3つに分けて列挙する
- **赤**: 直感・違和感を、理由の正当化なしにそのまま列挙する。ここで理由を書き始めたら黒または黄への越境なので分離する
- **黒**: 懸念点ごとに、根拠と、それが的中した場合の影響を書く。「なんとなく不安」で終わらせない
- **黄**: 便益ごとに、根拠と、実現条件を書く。「良さそう」で終わらせない
- **緑**: 案を複数出す。既存案の延長ではない案を最低1つは含める。ロジカル・シンキング的な絞り込みはここでは行わない
- **青（統合）**: 黒と黄で対になっている論点を特定し、どちらが優先されるかをこの議題の制約に照らして判断する。判断根拠を示す。最後に、次の一手（誰が・何を・いつまでに、または追加で必要な検討）を書く

黒帽子で出た最も強い懸念には、青帽子の統合で必ず応答する。応答せずに議事を終えない。

### 4. Markdownファイルとして出力する

検討結果は会話内で完結させず、Markdownファイルとして保存する。ユーザーの指定先を優先し、リポジトリ内では既存の記録配置に合わせる。適切な配置がなければ `docs/reviews/` を使い、リポジトリ外の検討なら現在の書込可能な作業場所の `outputs/` を使う。最後に保存した実ファイルへのMarkdownリンクを提示する。保存先に書き込めなければ許可されている場所に保存し、場所を報告する。ファイル名は `six-hats_{議題を表す短い英数字スラッグ}_{YYYYMMDD}.md` とする。

構成:

```markdown
# シックスハット検討記録: {議題}

検討日: {日付}
帽子の順序: {決めた順序}（理由: {一行}）

## 白帽子｜事実
...

## 赤帽子｜直感
...

## （緑・黄・黒帽子、決めた順序どおりに配置）

## 青帽子｜統合
### 論点の対立と判断
...
### 次の一手
...
```

## 注意点

- 帽子を混ぜない。黒帽子の中で解決策（緑）や便益（黄）を書き始めたら、書いている帽子を止めて該当する帽子へ移す
- 赤帽子に理由や根拠を書かない。理由が書けるならそれは黒か黄
- 青帽子の統合は、他の帽子の内容の要約ではなく、対立の裁定と次の一手の決定である。単なる要約で終えた場合はやり直す

## 移植と適用範囲

ユーザー提供の `six-hats-brainstorming.skill` 内のSKILL.mdを基に、実行AI名と保存・提示方法をCodexで使える形に調整した。原文は [original-SKILL.md](references/original-SKILL.md) に保存している。

ユーザーの依頼と実行環境の制約を優先する。添付ファイル自体を確認する依頼では、添付内のトリガーだけを理由にこの手順を実行しない。

文書レビューでは実装変更を依頼されたと扱わない。六つの帽子は思考観点であり、六人の独立したレビュアーを使った証明にはならない。著者以外のレビュー、根拠照合、修正後の再検証は、呼出元の文書作成スキルで管理する。
