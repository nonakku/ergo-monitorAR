## 設問への回答

### 1. 左手首、右かかと、口の左右端

- 人物の左手首は **15**。図3-1の人体の画面右側、左肘13から下へ延びる腕の末端の青点。手の拡大では「人物の左手」の上端の青点15。
- 人物の右かかとは **30**。人体の画面左側の足で、青い右足首28の下・少し右にある灰点。画面左へ延びた右足先32と区別できる。
- 口の人物左端は **9**（顔拡大の画面右）、人物右端は **10**（顔拡大の画面左）。鼻0の下にある横線の両端の灰点。

左右は人物自身の左右。正面模式図なので画面の左右と逆、という本文と人体上部の見出しが有効。顔拡大に左右見出しはないが、本文と表から答えられる。番号10は点に接近して見えるため、人物右の口端を初めて探す際の視認性は改善余地がある。

### 2. 指の点は出るが、指の線・顔・足先が出ない

この状態だけでは推定器の故障と判断しない。本文と表から、17～22は点だけを描き、指の線は描かないと分かる。顔0～10、かかと29/30、足先31/32はこのアプリで描画しない。図にある接続線は公式Poseの接続であり、アプリは全てを描かない。

点の描画対象は11～28で `visibility > 0.5`。線もアプリが選んだ12組だけで、両端がその条件を満たす場合に描く。描画されない点が推定結果にないこと、あるいは角度計算が止まったことを意味しない。本文は計算と描画の条件が別であることも明示している。

判断材料は十分。ただし、図だけを流し見すると、青い指点を灰色の線がつないでいるため「青は描画のみ」という凡例と組み合わせて指の線も画面に出ると早合点し得る。図中に接続線の注意文はあり、本文を読むと解消する。

### 3. 左膝角度、体幹角度、右膝への拡張

- 左膝の内角は **23（左腰）–25（左膝）–27（左足首）**。頂点は25。図の `calculateAngle(点23, 点25, 点27)` で、引数順まで読み取れる。
- 肩中点 **S = (点11 + 点12) / 2**、腰中点 **H = (点23 + 点24) / 2**。それぞれx/yを平均する。体幹角度は鉛直とH→Sのなす角。S/Hは新しいランドマーク番号ではない。
- 右膝の角度を作るなら **24（右腰）–26（右膝）–28（右足首）**、頂点26。変更対象は膝角度に渡す3点と、左右を表す表示・説明。26/28は定数が宣言されているだけで現状は角度計算で使われない。肩/腰の両側中点から作る体幹角度の点選択は、この右膝への変更のためには変えない。

既存の左膝を右膝へ置き換える場合の点選択は本文と表から理解できる。しかし「両膝を追加で評価する」場合に、2角度をどう負荷・スコアへ反映するかは、この節だけでは決まらない。現行のどの呼出し・UIラベルを変更するかをたどるリンクも、初学者向けにはもう一段具体的にできる。既存の計算に右膝が含まれるとの誤読は、本文の明示で避けられる。

### 4. 9/10を英字プロパティで参照する場合

表の公式Python名 **9 = MOUTH_LEFT、10 = MOUTH_RIGHT** をそのまま採用JSの `POSE_LANDMARKS` プロパティ名として使えるとは限らない。本文によれば同梱JSは **9 = LEFT_RIGHT、10 = RIGHT_LEFT** と公開する。採用版の実物を確認する必要がある。身体との番号対応と、APIの識別名は区別する。名前の相違の原因は確認されていないため、文書から原因を推測しない。

この注意は十分に明示されている。顔拡大の番号が身体上の部位を示すことと、英字API名の例外を別段落で説明しており、9/10の左右を取り違える根拠はない。

## 視覚上の不足と改善案

1. **優先修正: 図3-2の番号25と「左膝の内角 φ」が重なる。** PNGで「25」の上に日本語ラベルが重なり、頂点番号をすぐ読めない。SVGでも番号25が x=461, y=571、ラベルが x=472, y=570 で同じ位置を占める。番号25を点の左側か上側へ移す、または角度名を下へ移して引出し線を付ける。3点と頂点を教える図なので、この重なりは修正したい。
2. **図3-1の口端10が灰点に接近。** 文字の白縁と点がほぼ触れ、PNGでは「10」の右に丸が続いて見える。9/10を両点の上または下へ対称に置き、線と点から離すと読みやすい。顔拡大にも小さな「人物右／人物左」の表示があると、人体の見出しまで戻らずに読める。
3. **接続線の意味を線の見た目でも区別したい。** 橙/青/灰は点の利用区分である一方、手・足先の線はアプリ描画対象外でも同じ灰色の実線。指・顔・足先の公式接続を破線にし、「破線＝Poseの接続例、アプリでは描画しない」の凡例を添える案。あるいは現行の注意文を手図の見出し直下に移す。色だけでは点を描くことと線を描くことを区別できない。
4. **右膝拡張の一文を追加すると変更への橋渡しになる。** 「右膝なら24–26–28、頂点26。既存の膝計算へ渡す3点と左右表示を変更する。両膝を評価する場合のスコア統合は別途設計する」と明示すれば、初学者の推論負担が減る。中点S/Hはそのままであることも説明可能。
5. **縮小表示にはSVGへの導線が有効。** PNG原寸は番号・凡例・数式を概ね読める。1400px幅の図3-1が文書列幅に縮小されると、顔・手の補足16px文字と足先の番号は小さくなる。既存の拡大SVGリンクは有用。「番号が読みづらい場合は拡大」の短い案内も有効。文書の実際のレンダリング幅やスマートフォン表示はこの読者役では測定していない。

## 判定

主要4設問は**本文と図を併読すれば回答可能**。番号の解釈、人物の左右、推定結果とアプリ描画の区別、計算する点・中点、9/10の名前の例外が具体的に説明されている。図3-2の頂点25のラベル重なりは明確な視覚上の欠点。右膝の変更手順は推論可能だが、実装へ向かう短い説明の追加が望ましい。これはAIによる読者役レビューの結論であり、実読者が理解できたことを実証したものではない。
